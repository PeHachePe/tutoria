# Paso 0.1 · Crear el workspace y preparar Claude Code en Windows

06/11/2026 · Lo hace el autor, guiado por Claude (chat) · Commit: `chore: scaffold` (pendiente)

## Objetivo

Crear el proyecto Angular 22 y dejar Claude Code funcionando en Windows con el MCP de Angular, listo para el paso 0.2.

## Qué se hizo

### 1. Crear el proyecto

Proyecto creado con `ng new` en `D:\TutorIA\tutoria`. Comando previsto en el plan (confirma que usaste estos parámetros):

```
ng new tutoria --style=tailwind --ai-config=claude-code --ssr=false
```

Genera el repositorio git con un primer commit, Prettier configurado, `CLAUDE.md` con buenas prácticas de Angular y `.mcp.json` con el MCP del Angular CLI.

### 2. Instalar Claude Code en Windows

```
irm https://claude.ai/install.ps1 | iex
```

Resultado: se instaló, pero `claude` no se reconocía como comando.

### 3. Diagnosticar dónde quedó instalado

```powershell
Test-Path "$env:USERPROFILE\.local\bin\claude.exe"
```

Resultado: `True`.

```powershell
& "$env:USERPROFILE\.local\bin\claude.exe" --version
```

Resultado: `2.1.319 (Claude Code)`.

### 4. Añadir su carpeta al PATH del usuario

```powershell
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$env:USERPROFILE\.local\bin", "User")
```

Resultado: en una terminal nueva, `claude` ya funciona.

### 5. Comprobar los servidores MCP

```
claude mcp list
```

Resultado:

- `angular-cli: npx -y @angular/cli mcp`: pendiente de aprobación.

### 6. Aprobar el MCP de Angular

Se abrió `claude` y se eligió «Use this MCP server», no «all future MCP servers». Así cualquier servidor nuevo tendrá que aprobarse a mano.

### 7. Ver el estado con `/mcp`

- `angular-cli`: ✔ conectado, 9 herramientas.
- `claude-artifacts`: ✘. Viene integrado en Claude Code y no se necesita.

## Configuración resultante

`.mcp.json`, tal como lo genera `ng new`. En Windows funciona sin necesidad de `cmd /c`:

```json
{
  "mcpServers": {
    "angular-cli": {
      "command": "npx",
      "args": ["-y", "@angular/cli", "mcp"]
    }
  }
}
```

## Problemas y cómo se resolvieron

1. **`claude` no se reconocía después de instalarlo.** El ejecutable estaba en `%USERPROFILE%\.local\bin`, fuera del PATH. Se añadió esa carpeta al PATH del usuario.
2. **MCP `angular-cli` pendiente de aprobación.** Se aprobó solo ese servidor al abrir `claude`.
3. **¿Hacía falta `cmd /c` en Windows?** No: con Claude Code 2.1.319 el MCP conecta con el `.mcp.json` generado. El cambio queda en el plan como alternativa por si falla.
4. **Auto mode por defecto.** Claude Code decide solo qué acciones ejecutar. Se decide bloquear `git commit` y `git push` con reglas `deny` en la configuración de usuario (hecho en la sesión del paso 0.2).
