# Paso 0.0 · Planificación del desarrollo con Claude

06/11/2026 · Claude en Cowork, proyecto «TF» (modelo configurado: `claude-opus-5-5`) · Sin commit: solo documentación

## Objetivo

Revisar el plan de desarrollo v3 (julio de 2026) y dejarlo listo para arrancar la PEC3: tecnologías comprobadas contra las versiones actuales, forma de trabajar con Claude Code y entorno de Windows preparado.

## Qué se pidió

- Una estimación de la nota de la PEC2.
- Aclarar qué es SDD y cómo se compara con otros enfoques (se mencionó «Organic Driven Development»).
- Recuperar el documento SDD existente (`PLAN_DESARROLLO_TUTORIA.md`, v3).
- Revisar el plan de forma crítica: qué tecnologías sobran, cuáles cambiar y por qué, siempre con Angular 22 y sus buenas prácticas.
- Trabajar en local, con datos simulados y pantalla a pantalla.
- Decidir la librería de componentes, la gestión del estado, el proveedor de IA y la arquitectura, quitando lo que no aporte.
- Una bitácora detallada (tiempos, tokens, comandos) para la memoria y la presentación.
- Configuración para trabajar en Windows.

## Qué hizo Claude

1. Recuperó el contexto del proyecto: corrección de la PEC1, estado de la PEC2, enunciados, calendario oficial, TFM de la UNED y anteproyecto.
2. Estimó la PEC2 en un B (7–8), condicionado a si la falta de código se había pactado con la tutora.
3. Comprobó las tecnologías leyendo los paquetes publicados en npm (sus tipos y su `package.json`), no de memoria: Angular 22.2, Material 22.2, Angular Aria 22.2, Spartan 1.9, `@ngrx/signals` 22, Tailwind 4.3, Supabase, CodeMirror, Playwright, `angular-eslint`, `ccusage` y Claude Code.
4. Consultó la documentación oficial de la IA integrada en Chrome y de la API de Gemini. La búsqueda web no estaba disponible, así que solo se pudieron leer páginas concretas.
5. Reescribió el plan (v4 → v4.1) y el bloque del `CLAUDE.md`, y preparó plantillas para el registro, las decisiones, las fichas de pantalla y la bitácora.
6. Ajustó el plan en cada iteración según las decisiones del autor (ver más abajo).
7. Guió la instalación en Windows: el paso 0.1 tiene su propia bitácora.

## Comprobaciones hechas

- **Angular 22.2.4:**
  - `@Service()`, `injectAsync`, `resource()`, `httpResource()` y Signal Forms son estables;
  - `debounced()` es experimental;
  - `control()` no existe en Signal Forms.
- **`ng new` 22.2:**
  - zoneless, Vitest y OnPush vienen por defecto;
  - `--style=tailwind` y `--ai-config=claude-code` generan `CLAUDE.md` y `.mcp.json`;
  - Prettier ya viene incluido.
- **MCP del Angular CLI:** todas sus herramientas son estables (`get_best_practices`, `search_documentation`, `run_target`, `devserver_start`…).
- **Librerías de componentes:**
  - Material 22 se integra de forma nativa con Signal Forms;
  - Spartan 1.9 usa ControlValueAccessor;
  - Angular Aria solo trae 8 patrones.
- **IA integrada en Chrome:**
  - funciona en páginas web desde Chrome 148 y en español desde Chrome 149;
  - necesita 22 GB libres y más de 4 GB de VRAM, o bien 16 GB de RAM y 4 núcleos;
  - no funciona en móvil.
- **Gemini:**
  - tiene un endpoint compatible con la API de OpenAI;
  - su plan gratuito tiene modelos Flash, y Google puede usar el contenido para mejorar sus productos.
- **Requisitos:**
  - Angular CLI 22 pide Node 22.22.3 o posterior, o 24.15 o posterior;
  - Claude Code 2.1.319 se instala por npm con Node 22 o posterior.

## Problemas y cómo se resolvieron

- **Búsqueda web no disponible:** las versiones y APIs se verificaron leyendo los paquetes de npm y páginas concretas de la documentación oficial.
- **Errores en el plan v3:** usaba una API que no existe (`control()`) y otra experimental (`debounced()`). Corregido en la v4.
- **Desfase con la PEC2:** faltaban el rol de administrador, campos en el modelo de datos y el despliegue en Vercel. Incorporado.
- **Plazo de la PEC3:** pide una beta pública el 05/12, así que se reservó la cuarta semana para el despliegue.
