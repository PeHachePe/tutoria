# Paso 6.1c · Modo llamada: una conversación hablada con el tutor

22/11/2026 · Sesión de Claude Code (`claude-opus-5-5`) · Commits propuestos: `feat(voice): call mode with the tutor (step 6.1c)` y `docs: close step 6.1c (step 6.1c)`

## Objetivo

Que el alumno pueda hablar con el tutor por turnos y sin manos mientras programa (2.11, RF-08, CU-02 1a). Habla, el tutor contesta en voz alta y vuelve a escucharle. Une la síntesis (6.1a) y el dictado (6.1b) sobre el mismo `TutorStore`, que no cambia.

## Qué se pidió

Hacer el 6.1c según su plan de implementación, con cualquier mejora de UX, de UI o de código, siguiendo las buenas prácticas de Angular y diciendo lo que pudiera fallar. En la conversación, el autor:

- delegó en Claude la elección entre tres diseños de la llamada y aprobó las propuestas;
- preguntó si con auriculares se podía cortar al tutor hablando, y Claude cambió el ajuste a «Interrumpir al tutor hablando»;
- pidió evitar los `effect()` salvo que aporten mucho, y preguntó si el de `TutorSpeaker` lo era;
- preguntó para qué servían los temporizadores y si eran la mejor solución;
- probó la llamada en su navegador y vio que el tutor simulado contesta siempre lo mismo (es el guion de la demo);
- pidió una sola tecla para interrumpir, más rápida, y lo habló antes de decidir.

## Problemas y cómo se resolvieron

- **Dos `effect()` sobre los mismos turnos.** El plan daba a `VoiceCall` el suyo, y Angular no garantiza el orden respecto al de `TutorSpeaker`. Si el de la llamada iba primero, abría el micrófono con el tutor hablando. Con el autor de acuerdo, la llamada no tiene `effect()`: `TutorSpeaker` le avisa de cada respuesta (D-087).
- **La pregunta que se perdía.** Si el alumno interrumpía mientras la respuesta aún llegaba y volvía a hablar, `ask()` no hacía nada y la llamada se quedaba en «Pensando…». Ahora la pregunta espera. Primero se pensó en mirar cada 250 ms si ya se podía enviar; al preguntar el autor por los temporizadores, se cambió por el aviso `free()` de `TutorSpeaker`.
- **`quiet()` borraba `fromStandby`** justo después de calcularlo, y una respuesta en espera habría dado 90 s en lugar de 10. Se vio al repasar el código antes de probarlo.
- **La tarjeta crecía en «En espera»:** «Seguir hablando» y «Colgar» no cabían junto al texto. Los botones pasaron a una fila a todo el ancho y las cinco tarjetas miden lo mismo.
- **Dos mascotas con el chat vacío** (la del saludo y la de la tarjeta): durante la llamada, la del saludo se oculta.
- **El foco se perdía** al colgar desde la línea del tutor plegado: ahora vuelve a la mascota.
- **El micrófono de la pestaña del móvil salía gris:** los estilos de Material ganaban a `text-primary`. Se corrigió con `text-primary!`.
- **El lint rechazó** `pause` y `resume` como nombres de salidas (son eventos del DOM): pasaron a `hold` y `keepTalking`.
- **Un botón deshabilitado y enfocable recibe el clic** (`disabledInteractive`): «Dictar» y «Llamar al tutor» comprueban la llamada ellos mismos.
- **En la prueba en el navegador,** la llamada pasó a «En espera» sola. Era el panel del navegador ocultándose (la pestaña quedaba oculta), que es lo que tiene que hacer. Una recarga del servidor de desarrollo borró la simulación; antes de seguir se apagó la voz para que el tutor no sonara de verdad.
- **Cobertura:** el gesto de la mascota del panel durante la llamada era código muerto (la cara está en la tarjeta) y se quitó. Para la rama sin servicio de llamada en el campo se añadió un test.
- **Un test frágil** de Control sola fallaba con la máquina cargada: se fijó la hora en los dos extremos.

### La medición de los diez turnos (pendiente del autor)

Con `npm run db:start` y `npm run start:local` (la clave del proveedor en `supabase/functions/.env`), en Safari o Edge: diez turnos de llamada seguidos, sin recargar la página. Después, en la consola:

```js
(() => {
  const NAMES = {
    'tutoria-call-last-word': 'lastWord',
    'tutoria-call-sent': 'sent',
    'tutoria-call-first-text': 'firstText',
    'tutoria-call-first-sound': 'firstSound',
  };
  const marks = performance
    .getEntriesByType('mark')
    .filter((m) => m.name in NAMES)
    .sort((a, b) => a.startTime - b.startTime);
  const turns = [];
  for (const m of marks) {
    if (NAMES[m.name] === 'lastWord') turns.push({});
    const turn = turns.at(-1);
    if (turn) turn[NAMES[m.name]] = m.startTime;
  }
  const rows = turns
    .filter((t) => t.sent && t.firstText && t.firstSound)
    .map((t) => ({
      'última palabra → envío': Math.round(t.sent - t.lastWord),
      'envío → primer texto': Math.round(t.firstText - t.sent),
      'primer texto → primer sonido': Math.round(t.firstSound - t.firstText),
      'envío → primer sonido': Math.round(t.firstSound - t.sent),
    }));
  const median = (xs) => {
    const s = [...xs].sort((a, b) => a - b);
    const i = Math.floor(s.length / 2);
    return s.length % 2 ? s[i] : Math.round((s[i - 1] + s[i]) / 2);
  };
  console.table(rows);
  const medians = Object.fromEntries(
    Object.keys(rows[0] ?? {}).map((k) => [k, median(rows.map((r) => r[k]))]),
  );
  console.table([medians]);
  return medians;
})();
```

Si la mediana de «envío → primer sonido» pasa de 2000 ms, o el autor nota la pausa, se hace el 6.1d. La tabla de los diez turnos y sus medianas irá aquí.

## Para la presentación

- La llamada no es un canal aparte: lo dicho acaba en el mismo chat, que también se puede escribir. Una pregunta escrita durante la llamada también se oye, y lo entendido se corrige con un clic («Corregir») o se descarta con Esc antes de que se envíe.
- Un micrófono abierto en un aula oye a los compañeros: la llamada se pone en espera sola tras 90 s sin voz o al ocultar la pestaña, y el micrófono abierto siempre se ve (el anillo de la mascota, la pestaña del móvil).
